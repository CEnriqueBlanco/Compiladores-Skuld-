SINTAXIS LÉXICA COMPLETA (RECONOCIMIENTO DE TOKENS)
---------------------------------------------------

1) REGLAS GENERALES DEL LEXER
-----------------------------
- El análisis léxico recorre el código de izquierda a derecha.
- Se aplica regla de "maximal munch" (coincidencia más larga).
- Cuando dos tokens compiten con la misma longitud, gana el de mayor prioridad:
  1. Comentarios
  2. Literales de cadena
  3. Literales numéricos
  4. Palabras clave
  5. Identificadores
  6. Operadores compuestos
  7. Operadores simples
  8. Delimitadores
- Espacios, tabs y saltos de línea se ignoran; el lexer actúa como si todo estuviera en una sola línea.

2) TOKENS IGNORADOS / COMENTARIOS  (Color 3 → COMMENTS #696969)
-------------------------------------------------------------------
WHITESPACE:
  - Regla: ignorado por completo.
  - Acción: avanzar posición sin producir tokens.

COMMENT_LINE  (una línea, estilo C):
  - Sintaxis: <> texto hasta fin de línea
  - Regex: <>[^\n]*
  - Acción: Ignorar. Resaltar con Color 3.
  - Ejemplo: <> El Psy Kongroo

COMMENT_BLOCK  (múltiples líneas, estilo C):
  - Sintaxis: <! texto en varias líneas !>
  - Regex aproximada: <!([^!]|!(?!>))*!>
  - Acción: Ignorar. Resaltar con Color 3.
  - Error: si no cierra con !> antes de EOF → ERROR_LEXICO.
  - Ejemplo:
      <! Esto es un
         comentario
         de bloque !>

3) PALABRAS RESERVADAS (KEYWORDS)
---------------------------------
Regex base de palabra clave exacta:
  - Debe coincidir completa, no como prefijo de identificador.
  - Ejemplo: "gate" es KEYWORD, "gateway" es IDENTIFIER.

Lista completa (todas con Color 4 — KEYWORDS #c41e3a):
  - labmem
  - worldline      (= int)
  - divergence     (= float)
  - dmail          (= cout)
  - sphone         (= cin)
  - reading
  - choice         (= if)
  - else
  - fork           (= switch)
  - path           (= case)
  - gate           (= main)
  - loop           (= while)
  - pulse          (= do)
  - seal           (= end)
  - shift
  - jump
  - return
  - steiner
  - and            (también acepta &&  — Color 6 como operador)
  - or             (también acepta ||  — Color 6 como operador)
  - not            (también acepta !   — Color 6 como operador)
  - void
  - true
  - false

Tokens sugeridos:
  - KW_LABMEM, KW_WORLDLINE, KW_DIVERGENCE, KW_DMAIL, KW_SPHONE, KW_READING
  - KW_CHOICE, KW_ELSE, KW_FORK, KW_PATH, KW_GATE, KW_LOOP, KW_PULSE, KW_SEAL
  - KW_SHIFT, KW_JUMP, KW_RETURN, KW_STEINER
  - KW_AND, KW_OR, KW_NOT, KW_VOID, KW_TRUE, KW_FALSE

4) IDENTIFICADORES
------------------
IDENTIFIER:
  - Regex: [A-Za-z_][A-Za-z0-9_]*
  - Regla: Si el lexema está en la tabla de keywords, se clasifica como KEYWORD.
  - Ejemplos válidos: alpha, beta_1, calcular_divergencia, _tmp
  - Ejemplos inválidos: 1abc, @valor

5) LITERALES
------------
INTEGER_LITERAL (worldline):
  - Regex: 0|[1-9][0-9]*
  - Ejemplos: 0, 7, 120

FLOAT_LITERAL (divergence):
  - Regex recomendada: ([0-9]+\.[0-9]+)([eE][+-]?[0-9]+)?
  - Regla adicional: si es menor que 1, debe escribirse con 0 antes del punto.
  - Ejemplos: 1.048596, 0.0, 0.32, 2.5e-3

STRING_LITERAL (dmail):
  - Delimitador: comillas dobles
  - Regex conceptual: "([^"\\]|\\["\\nrt])*"
  - Escapes soportados: \", \\, \n, \r, \t
  - Ejemplos: "Hola", "Iteración: "
  - Error: cadena sin cierre antes de fin de línea/archivo.

BOOLEAN_LITERAL (reading):
  - Lexemas: true | false
  - Nota: pueden tokenizarse como KW_TRUE/KW_FALSE o BOOL_LITERAL.

6) OPERADORES
-------------
ARITMÉTICOS:
  - +  
  - -  
  - *   
  - /   
  - %   

ASIGNACIÓN:
  - =   
  - +=  
  - -=  
  - *=  
  - /=  
  - %= 

INCREMENTO/DECREMENTO:
  - ++  
  - -- 

RELACIONALES:
  - ==  
  - != 
  - <   
  - <=  
  - >   
  - >= 

E/S CON PARÉNTESIS (estilo función):
  ⚠ ÚNICA forma válida. No se usan operadores stream << ni >>.
  - dmail("texto")   (STREAM_OUT)  -> salida estándar
  - dmail(variable)  (STREAM_OUT)  -> salida de variable
  - sphone(variable) (STREAM_IN)   -> entrada estándar
  Ejemplos:
      dmail("Hola mundo");
      dmail(x);
      sphone(nombre);
      sphone(x);

LÓGICOS  (Color 6 → OPERATORS #ffffff):
  ⚠ ÚNICOS operadores que aceptan tanto forma de palabra como símbolo.
  El resto de operadores del lenguaje SOLO aceptan su forma simbólica.
  - and  / &&   (AND_OP)  → ambas formas válidas
  - or   / ||   (OR_OP)   → ambas formas válidas
  - not  / !    (NOT_OP)  → ambas formas válidas
  Regla de prioridad: "&&", "||", "!" se reconocen como operador;
  "and", "or", "not" se dectectan como keyword y mapean al mismo token.

Sintaxis de E/S en Skuld:
  - Salida:  dmail("Hola");
             dmail(x);
  - Entrada: sphone(x);
             sphone(nombre);

----------------------------------------
  - (  
  - )   
  - {  
  - }   
  - [   
  - ]   
  - ;   
  - ,   
  - .   
  - :   

8) TABLA RESUMEN DE REGEX PRIORITARIA
-------------------------------------
Orden sugerido de matching (de mayor a menor prioridad):
  1. <>[^\n]*
  2. <!([^!]|!(?!>))*!>              (si habilitas bloque)
  3. "([^"\\]|\\["\\nrt])*"
  4. ([0-9]+\.[0-9]+)([eE][+-]?[0-9]+)?
  5. 0|[1-9][0-9]*
  6. [A-Za-z_][A-Za-z0-9_]*           (luego validar keyword)
  7. ==|!=|<=|>=|\+\+|--|\+=|-=|\*=|/=|%=|&&|\|\|
  8. [=+\-*/%<>!(){}\[\];,.:]
  9. [ \t\r\n]+         (ignorado)

9) ERRORES LÉXICOS A REPORTAR
-----------------------------
- Carácter no reconocido (ej: @, #, `) fuera de strings/comentarios.
- Cadena no terminada.
- Comentario de bloque no terminado (si se habilita).
- Número mal formado (ej: 12..3, 1e, .32, 09 si prohíbes ceros a la izquierda).
- Secuencia de escape inválida en string (ej: \q).

Formato recomendado de error:
  ERROR_LEXICO(linea, columna): <descripcion> -> '<lexema>'

10) EJEMPLO DE TOKENIZACIÓN
---------------------------
Entrada:
  labmem worldline x = 10;

Salida de tokens:
  [KW_LABMEM:"labmem"]
  [KW_WORLDLINE:"worldline"]
  [IDENTIFIER:"x"]
  [ASSIGN:"="]
  [INTEGER_LITERAL:"10"]
  [SEMICOLON:";"]

-----------------------------------

- Mantener tabla de símbolos separada (el lexer solo reconoce tokens).

EJEMPLO DE CÓDIGO SKULD
------------------------
<> Programa: Calculadora de Divergencia
<> El Psy Kongroo!

labmem divergence alpha = 1.048596;
labmem divergence beta = 0.0;

steiner divergence calcular_divergencia(worldline a, worldline b) {
    labmem divergence resultado = 0.0;
    resultado = (a + b) / 2.0;
    return resultado;
}

steiner void mostrar_mensaje(dmail mensaje) {
    dmail(mensaje);
}

gate {
    labmem worldline x = 10;
    labmem worldline y = 20;
    
    beta = calcular_divergencia(x, y);
    
    choice (beta > alpha) {
        mostrar_mensaje("¡Worldline alcanzada!");
    } else {
        mostrar_mensaje("Divergencia insuficiente");
    }
    
    loop (x < 5) {
        dmail("Iteración: " + x);
        x = x + 1;
    }
}
